# asis — issue から始めて、PR をつなぐ

asis は、状態を誰にも入力させず、GitHub の事実(ブランチ・PR・レビュー・チェック・取り込み・デプロイ)だけで
「今どこまで進んでいて、次は誰の番か」を出す。PR がどの issue の仕事かは、次の 2 つの書き方から読む。
**守ることは 2 つだけ。**

1. **ブランチ名を issue の番号で始める。** `12-short-name`。種類を前に付ける決まりの repo では `feature/12-short-name`(最後の区切りの頭が番号)
2. **PR の本文に issue を書く。** その PR で issue が終わるなら `Closes #12`、途中なら `Refs #12`

その repo に別の決まり(CLAUDE.md・CONTRIBUTING.md のブランチ名や PR の書き方)があれば、そちらを優先する。
ブランチ名に番号を入れられない repo では、2 だけで足りる(ただし PR を出すまで、作業中であることは asis に出ない)。

## 「#12 を始めて」と言われたら

1. issue を読む。`gh issue view 12`(別の repo なら `-R owner/repo`)
2. 本文の **目的** と **できたと言える条件** を、作業の指示として扱う。条件が曖昧で作業の向きが決まらないときは、始める前に聞く
3. ブランチを切る。名前は `12-` で始め、あとは短い英語の説明(`12-add-login`、決まりがあれば `feature/12-add-login`)。worktree を使う repo なら、worktree もこのブランチで作る
4. 実装する。その repo の決まり(テスト・lint・PR の書き方)に従う
5. PR を出す。本文に `Refs #12` か `Closes #12` を書く
   - 1 つの issue に PR を何本 出してもよい。途中の PR は `Refs`、最後の 1 本だけ `Closes`
   - 別の repo の issue なら `Refs owner/repo#12`
   - PR の上に積んだ PR は、下の PR と同じ issue につながる(書かなくてよい)

## 「issue にして」と言われたら

話の中身から、次の 2 つを書いて起票する。`gh issue create`

```markdown
## 目的
何のために、何を変えるか。2〜3 文。

## できたと言える条件
- [ ] 確かめられる形で 1 行ずつ(「〜が出る」「〜のとき〜になる」)
```

- 題は、できあがったら何が変わるかを 1 行で
- 条件は、あとで本人か AI が「できた / まだ」を言える形にする。作り方の指定は書かない
- 起票したら、番号を伝える。そのまま始めるかは聞く

## 作業の途中で見つけて、今回は直さないもの

新しい issue にする。本文の最初に、元の issue を書く(`#12 の作業中に見つけた`)。
PR の本文や issue のコメントに積まない(埋もれて、あとから引けない)。

## やらないこと

- **状態を issue に書かない。**「着手しました」「レビュー待ちです」「完了しました」のコメント・ラベル・題の書き換えをしない。状態は asis が事実から出す
- **issue を手で閉じない。** `Closes #12` を書いた PR が取り込まれると、GitHub が閉じる
- 番号を推測で書かない。issue が無い作業は、issue 無しのまま PR を出してよい(asis には「タスクにつながっていない PR」として出る)
