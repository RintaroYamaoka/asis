# asis — issue から始めて、PR をつなぐ

asis は、状態を誰にも入力させず、GitHub の事実(ブランチ・PR・レビュー・チェック・取り込み・デプロイ)だけで
「今どこまで進んでいて、次は誰の番か」を出す。PR がどの issue の仕事かは、次の 2 つの書き方から読む。
**守ることは 2 つだけ。**

1. **ブランチ名を issue の番号で始める。** `12-short-name`。種類を前に付ける決まりの repo では `feature/12-short-name`(最後の区切りの頭が番号)
2. **PR の本文に issue を書く。** その PR で issue が終わるなら `Closes #12`、途中なら `Refs #12`

その repo の CLAUDE.md・CONTRIBUTING.md に決まりがあれば、そちらを優先する。とくに次の 2 つは、始める前に必ず確かめる。

- **`Closes` を書かないと決めている**(実機で確かめてから閉じる、など):その PR は `Refs #12` にする。閉じるのは、決まりどおり確かめが取れてから、手で
- **起票する人を決めている**(計画の担当が決める、など):AI は issue を起票しない。下の「issue にして」「今回は直さないもの」も、その repo の決まりの置き場に従う

ブランチ名に番号を入れられない repo では、2 だけで足りる(ただし PR を出すまで、作業中であることは asis に出ない)。

### 計画を issue でなく文書(計画書・指摘台帳)に書いている repo

タスクの番号が issue でなく文書の番号(`AR-7`・`S-263`・`IF-69` など)の repo では、その repo で書いている人の付け方にそろえる。
その人の手元の道具(ターミナルの看板など)は、ブランチ名と PR の題でカードを結んでいる。こちらの付け方を持ち込むと、その人の手元で作業がつながらなくなる。

- **ブランチ名に issue の番号を入れない。** その repo の直近の PR のブランチ名を見て、同じ形にする(`種類/` のあとに文書の番号を小文字で詰めて、短い英語の説明。`feat/if69-entrance-keys`・`fix/s129-phone-after-expiry`)
- **PR の題の終わりに、文書の番号をその repo の書き方で入れる。**(`feat: 説明（計画書 §7-4c・AR-7・台帳 S-263）`)。書き方は、その repo の直近の PR の題を見てそろえる
- 番号が分からなければ、推測で書かずに人に聞く

## 「#12 を始めて」と言われたら

1. issue を読む。`gh issue view 12`(別の repo なら `-R owner/repo`)
2. 題と本文を、そのまま作業の指示として扱う。issue は短く漠然と書かれることが多い。決められない所は、始める前にその場で人に聞く(issue の書き直しは求めない)
3. ブランチを切る。名前は `12-` で始め、あとは短い英語の説明(`12-add-login`、決まりがあれば `feature/12-add-login`)。worktree を使う repo なら、worktree もこのブランチで作る
4. 実装する。その repo の決まり(テスト・lint・PR の書き方)に従う
5. PR を出す。本文に `Refs #12` か `Closes #12` を書く
   - 1 つの issue に PR を何本 出してもよい。途中の PR は `Refs`、最後の 1 本だけ `Closes`
   - 別の repo の issue なら `Refs owner/repo#12`
   - PR の上に積んだ PR は、下の PR と同じ issue につながる(書かなくてよい)

## 「issue にして」と言われたら

起票する人を決めている repo では起票しない。決める人に任せることと、その repo の決まりの置き場(未決の欄など)を伝える。
それ以外の repo では、話の中身から次の 2 つを書いて起票する。`gh issue create`

```markdown
## 目的
何のために、何を変えるか。2〜3 文。

## できたと言える条件
- [ ] 確かめられる形で 1 行ずつ(「〜が出る」「〜のとき〜になる」)
```

- 題は、できあがったら何が変わるかを 1 行で
- 条件は、あとで本人か AI が「できた / まだ」を言える形にする。作り方の指定は書かない
- 起票したら、番号を伝える。そのまま始めるかは聞く

## 作業の途中で見つけて、今回は直さないもの

新しい issue にする。本文の最初に、元の issue を書く(`#12 の作業中に見つけた`)。
起票する人を決めている repo では起票せず、その repo の決まりの置き場に 1 行で残す。
PR の本文や issue のコメントに積まない(埋もれて、あとから引けない)。

## やらないこと

- **状態を issue に書かない。**「着手しました」「レビュー待ちです」「完了しました」のコメント・ラベル・題の書き換えをしない。状態は asis が事実から出す
- **issue を手で閉じない。** `Closes #12` を書いた PR が取り込まれると、GitHub が閉じる。例外は `Closes` を書かないと決めている repo で、確かめが取れたあとに閉じるとき
- 番号を推測で書かない。issue が無い作業は、issue 無しのまま PR を出してよい(asis には「タスクにつながっていない PR」として出る)
